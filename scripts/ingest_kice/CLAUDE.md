# 정답지 파싱 (ingest_kice)

기출 회차마다 **정답 소스가 다르다.** 시험 유형으로 파서를 골라야 한다. 그리고 단답형
정답은 사제 수식폰트(HyhwpEQ 계열)로 **PUA(Private Use Area) 인코딩**돼 일반 텍스트
추출이 깨진다 — 반드시 디코드할 것. *이걸 잊고 "단답을 못 읽는다"로 오진하지 말 것.*

## 정답 소스 ↔ 파서 (시험 유형별)

| 시험 유형 | 구성 | 정답 소스 | 파서 |
|---|---|---|---|
| 평가원 수능·모평 | 공통22 + 선택3×8 (46) | 별도 `정답.pdf` | `parse_answer_table` (ingest_v2 경유) |
| 통합형 수능 (2028 예시) | 단일 30 | 별도 `정답.pdf` | `parse_single_answer_table` |
| 2021 수능 가/나형 | 단일트랙 30 ×2 | **텍스트 정답표** (문항/정답/배점 triplet, **홀수형 기준**, 배점합=100) | `ingest_ganah.parse_answers` |
| 교육청 고3 모의고사 | 공통1-22 + 선택23-30 | **`해설.pdf` 정답표** | `parse_haesol_answers` |
| 교육청 고1·고2 학평 | 단일 30 (객관1-21, 단답22-30) | **`해설.pdf` 정답표** (별도 정답.pdf 없음) | 단일과목 분기 (아래) |

평가원은 별도 `정답.pdf`가 오지만, **교육청 학평(고1/고2)은 `해설.pdf` 안의 정답표가
유일한 소스**다.

## 사제 폰트 글리프 인코딩 — 핵심 (`_circled` / `_ht_dec` / `_decode_single_ans`)

정답 글리프가 폰트 서브셋마다 **다른 코드포인트**로 들어와 일반 텍스트 추출이 깨진다. 3종:

| 글리프 | 코드포인트 | 디코드 | 쓰임 |
|---|---|---|---|
| 유니코드 동그라미 `①~⑤` | U+2460~2464 | `CIRCLED` 맵 | 객관식 (HyhwpEQ 회차) |
| HyhwpEQ PUA | U+E034~E03D | `(cp-0xE033)%10` → E034=1…E03D=0 | 단답 숫자 (HyhwpEQ 회차) |
| CJK 글리프 서브셋 | U+6ABE~6AC2 (檾檿櫀櫁櫂) | `cp-0x6ABE+1` → ①…⑤ | 객관식 (일부, 예 2021 11월 학평) |

- 세 인코딩은 `_circled(ch)`(동그라미)·`_ht_dec(ch)`(+PUA·ascii)·`_decode_single_ans` **한 곳**에서 흡수.
- **다자리 단답**(예: 720, 149)은 연속 PUA 글리프를 x좌표 인접(<12px)으로 이어붙여 복원.
  CJK 글리프를 쓰는 회차는 단답이 **평문 ASCII**(글리프 아님).
- 폰트 서브셋이라 코드포인트가 회차마다 또 바뀔 수 있음 → **새 글리프 만나면 정답표를 렌더해
  눈으로 대조한 뒤** 매핑(범위)을 추가할 것. (CJK 매핑도 고2 11월 정답표 렌더 대조로 확정했음.)

## 고3 정답표 (`parse_haesol_answers`) — 2단 좌표 + 22/23 라우팅

해설 정답표는 **2단(column)** 이라 텍스트 추출 순서가 행을 가로질러 섞인다 → 순서가 아니라
**좌표**로 읽는다:

- `_ht_regions(doc)` → `(page, column, 셀클러스터)` (y-gap으로 행 묶음 + 컬럼 분리).
- `_ht_coord_dandab(chs, col, pw, cell_ys, lo, hi)` → 각 행 y에서 번호(ascii) + 뒤 PUA를 디코드.
- 영역 라우팅 = **공통 ≤22 / 선택 ≥23**. ⚠️ 이 이분법은 **고3 전용**(단답 22는 공통, 23-30 선택).
  단답이 22부터인 단일과목엔 안 맞아 22-30이 스킵됨 → 단일과목은 아래 별도 경로.

## 단일과목 정답표 (`parse_haesol_single` → `_table_single`) — 격자 테두리

고1·고2 학평·통합형은 단일 30(객관1-21, 단답 **22**-30). 회차마다 폰트·레이아웃이 제각각이라
좌표 휴리스틱이 취약하다 — 같은 정답표가 인터리브(`1④2②`) / 번호행·정답행 분리 / 2열 packed
(`111616`) 로 뒤섞여 나온다. → **PyMuPDF `find_tables(strategy="lines")`** 로 정답표의 격자
테두리를 잡아 **셀 단위**로 추출하면, 텍스트레이어 순서 혼란을 격자선이 무시해 깨끗하다:

```python
for tb in page.find_tables(strategy="lines").tables:
    for row in tb.extract():        # 셀 예: ['1','③','2','④',…] · CJK ['1','櫁',…] · 단답 ['26','7',…]
        # 번호셀(1..30) + 바로 뒤 셀(정답) 페어링; 글리프면 _decode_single_ans, 평문이면 그대로
```

- 검증: 고1·고2 3·6·9·11월 + 2026 6월 = **30/30** (인터리브·분리·packed·CJK·ascii 단답 전부 흡수).
- 테두리 없는 정답표(미검출)만 구 좌표/PUA 경로(`_ht_regions`+`_ht_coord_dandab`)로 빈 번호 보강.
- **비전 안 씀** — 전부 결정적 텍스트레이어 디코드.

## 검증 절차

객관식 1-21을 raw 텍스트 정답표(`①②③…`)와 대조 → 일치하면 같은 격자에서 읽은 단답(22-30)도
신뢰 가능. 인제스트 후 `/verify-answers`로 골든 PDF 교차검증 권장.
