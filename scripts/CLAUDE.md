# 풀이 캐시 & 솔버 (build_solution_cache.py)

## 용어: **"솔버"** (이전 오칭 "검증기" 폐기)

`db/solutions/<slug>.py` 는 단순 *답 검증기*가 **아니다**. 문제의 **수학 구조를 파라미터화한
솔버** — 주어진 조건 → 답의 관계를 코드로 인코딩한 것이다.

- **핵심 용도 = 유사문제 무한 재생성.** 문제 속 파라미터(숫자·조건)를 바꿔 **같은 유형의 새
  문제를 검증된 답과 함께** 무한히 찍어낸다. 이게 학습 시스템의 본질적 이유.
- 부수 용도: 정답표 독립 검증 (원식에 답 역대입 → 정답표 파싱 오류·모델 오답을 *정답표와
  무관하게* 잡아냄. 2026 오염이 이 구멍이었다).
- ⚠️ **"검증기"라 부르면 용도가 '답 체크'로 한정돼 보인다 → 항상 "솔버"로 부를 것.**

## gold-match 는 솔버가 아니다

단답형을 `verifier: gold-match`(모델답 == 정답표 일치)로만 캐시하면 **솔버가 없는 상태**다:
재생성도 독립검증도 불가. **객관식·단답 모두 솔버 필수.**

> ⚠️ 설계 구멍: 현재 build_solution_cache 는 `use_verifier = (fmt=='choice')` 라 **단답엔 솔버를
> 안 만든다**. 단답 962개가 gold-match뿐(솔버 없음) → 메워야 함. (3324 중 솔버 없는 983개:
> 단답 gold-match 962 + opus-hand 손풀이 20 + etc.)
