Stage C — figure_spec 자동 추출

변경 사항

1. Content schema 확장 (web/src/content.config.ts) 
// problems collection 에 figure_spec 필드 추가
figure_spec: z.object({
  kind: z.enum(['geometry', 'plot', 'numberline', 'chart']),
  spec: z.record(z.unknown()),
  confidence: z.number().min(0).max(1).optional(),
}).optional()
2. VISION_SYSTEM prompt 에 spec 추출 명령 추가 (scripts/ingest_kice/vision_meta.py) 
vision LLM이 도형 있으면 우리 4종 컴포넌트 중 적합한 형식의 spec JSON 생성:
- plot: 함수 그래프 ({fn, range, points})
- geometry: 평면도형 ({shapes: [point/segment/circle...]})
- numberline: 구간/부등식 ({range, marks, intervals})
- chart: 히스토그램/표 ({kind, bins, freq})

confidence < 0.5 또는 표현 어려우면 null → searchable_text 의 [그림] 묘사가 fallback.

Spec 적용 가능 도형 분류 (예상)

도형 종류spec적용 가능률
함수 그래프 (포물선/지수/로그)plot90%
좌표평면 + 점·선분geometry80%
삼각형·원·접선geometry70%
부채꼴 + 호geometry (호 + 부채꼴 shape)60%
수직선 부등식 해numberline95%
히스토그램/도수분포chart70%
3D 입체 (정육면체/원뿔)X (현재 X)0% — PNG fallback
회전체 단면X0%
일러스트 (학생 그림 등)X0%
다중 보조선/복잡한 합동/유사 도형geometry (낮은 confidence)40%
예상 spec 추출 성공률: 60-75% 실패는 searchable_text [그림 묘사]로 fallback

downstream 활용

  1. UI 재렌더: problem 페이지에서 PNG 옆에 SVG 도형 추가. 확대 가능, 좌표 hover. (별도 컴포넌트 작업 필요)
  2. LLM 튜터 system prompt: figure_spec JSON 을 본문에 포함. 텍스트 묘사보다 구조화돼 풀이 정확도 ↑
  3. 도형 변형 풀이: 튜터가 "보조선 BD를 그어보자" 시 spec 베이스로 변형 도형 emit 가능

리스크 / Trade-off

  • cost: 같은 vision LLM 호출 안에서 spec 도 추출 — 추가 비용 없음 (output token 만 늘어남, ~10-20%)
  • schema 마이그레이션: 기존 1389 problem 들은 figure_spec=undefined. 새 인제스트만 채워짐
  • spec 생성 정확도: 좌표/각도 추정이 어긋나면 SVG 가 PNG와 다르게 보일 수 있음. confidence 필드로 신뢰도 표시 + 낮으면 spec 안 보이게
  • UI 컴포넌트 미통합: 본 stage는 데이터 layer 만 — 실제 SVG 렌더 통합은 별도 작업
