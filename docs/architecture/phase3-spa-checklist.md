# Phase 3 — SSR 제거 → SPA 실행 체크리스트

> 2026-08-15 작성. 로드맵 [app-roadmap.md](app-roadmap.md) Phase 3 의 실행 계획.
> **일반론이 아니라 실측에서 나온 순서다.** 아래 숫자는 전부 이 레포를 직접 세어 얻었다.

## 왜 이 공사가 병목인가

전체 56항목 중 40개가 남았는데, 그중 **33개(Phase 5~8)가 Phase 3 뒤에 줄 서 있다.**
Phase 4 가 6/6 로 끝났는데도 앞으로 못 가는 게 그 증거다. 여기가 뚫려야 나머지가 움직인다.

## 실측 — 25개 페이지의 실제 성격

| 성격 | 개수 | 페이지 |
|---|---|---|
| **A. 마크다운 렌더** (`<Content>`) | **4** | `concepts/[...slug]` `problems/[...slug]` `mistakes/[slug]` `syntheses/[slug]` |
| **B. 콘텐츠 목록** (컬렉션만) | 8 | `concepts/index` `problems/index` `problems/units` `mistakes/index` `syntheses/index` `exam/random` `exam/round/[key]` `tools` |
| **C. 사용자 상태·DB** | 11 | `index` `atlas` `graph` `paths` `progress` `account` `settings` `log` `exam/index` `privacy` `terms` |
| **D. 인증** | 2 | `login` `signup` |

**이미 클라이언트에서 도는 것**: 17개 페이지가 Astro 아일랜드나 인라인 script 를 갖고 있다
(`concepts/[...slug]` 7개, `problems/[...slug]` 4개, `index` 4개…). **순수 SSR 은 8개뿐**이다.

→ ★**"25개를 전부 새로 만든다"가 아니다.** 상당수는 이미 클라이언트 로직을 갖고 있고,
  서버가 만들어주던 **껍데기(HTML)와 데이터 공급**만 바꾸면 된다. 공사 규모를 여기서 다시 잡았다.

**API 현황**: 엔드포인트 25개가 이미 있다. 다만 전부 **행위**용(`chat` `attempt` `progress`…)이고
**콘텐츠 목록**용은 하나도 없다 — B 그룹이 필요로 하는 게 그것이다.

## 순서를 이렇게 잡은 이유

A(마크다운)가 **가장 어렵고 가장 근본**이다. 링크 재작성이 빌드 시 `docs/` 전체를 훑어 만든
지도(`CONCEPT_LEAF_MAP`)를 쓰므로 **원리적으로 브라우저에서 못 돈다.** 그래서 A 를 먼저 풀지
않으면 B·C 를 아무리 옮겨도 핵심 화면(개념·기출)이 안 된다.

거꾸로 A 를 "빌드 시 선렌더"로 풀면 **부수 효과가 크다** — 콘텐츠가 정적 파일이 되므로
기기에 캐시할 수 있고, 그게 곧 **오프라인 동작**이다. 앱을 앱답게 만드는 게 이 한 수다.

          **Phase 5 의 전 구간 압축이 켜지면 여기서 가장 크게 먹는다.**

      → 교훈: **`getCollection` 을 쓴다고 목록 페이지가 아니다.** 합성 화면은 페이지 전용
        엔드포인트가 답이고, 그건 "목록을 클라이언트로 던지는" 것과 **다른 종류의 일**이다.

**전환 패턴(확정)** — 나머지는 이 반복이다:
1. 껍데기(제목·h1·설명)는 `.astro` 에 **남긴다**. 전부 옮기면 원본 HTML 이 비어 회귀를 못 잰다.
2. 목록만 React 아일랜드로. 데이터는 `useContentIndex(collection)` 훅 한 벌.
3. **로딩·0건·에러를 세 상태로 구분**한다. 에러를 0건으로 뭉개면 "자료가 없다"로 잘못 읽힌다.
4. 브라우저로 실제 렌더를 확인한다(아래).

**함정 셋 — 전환하며 실제로 밟았다**
- ★**Astro 아일랜드는 직렬화 가능한 props 만 받는다.** 렌더 프롭(함수)·JSX 를 넘기는 공통
  컴포넌트를 먼저 만들었다가 폐기했다 — 런타임에 깨진다. 공통은 **훅**으로만 가능하다.
- ★**Astro 컴포넌트는 아일랜드 안에서 못 쓴다.** `ConceptCard.astro` → `ConceptCard.tsx` 를
  1:1 로 만들었다. ⚠️ 두 벌이 갈라지면 화면이 페이지마다 달라 보인다. 3단계 끝나면 `.astro` 를 지운다.
- ★**방출물의 날짜는 문자열이다**(SSR 은 `Date` 객체였다). `toISOString()` 을 부르면 깨진다.

**렌더 검증 수단** — 컨테이너에 헤드리스 브라우저·DOM 라이브러리가 **하나도 없다**.
클라이언트 렌더는 원본 HTML 로 못 재므로 이렇게 본다:
```bash
ssh -N -L 14399:127.0.0.1:4399 tme    # 검증서버(DEV_NOAUTH)는 tme 의 127.0.0.1 전용
```
그 뒤 브라우저로 `http://127.0.0.1:14399/<경로>`.
· ⚠️ **fetch 완료 전에 읽으면 "불러오는 중…" 만 보인다.** 실제로 첫 확인에서 실패로 오인했다 —
  한 번 더 읽으면 목록이 있다.

## 측정을 믿기 전에 확인할 것 (이번 공사에서 실제로 세 번 당했다)

같은 계열의 착각이 반복된다 — **검증이 통과한 게 아니라 검증이 대상을 못 본 것**이다.

| 증상 | 실제 원인 |
|---|---|
| "타입체크 0 에러" | **푸시를 안 해서** 컨테이너가 옛 코드를 검사했다 |
| "가드가 안 문다(exit 0)" | `... \| tail` 뒤의 `$?` 는 **tail 의 종료코드**다 |
| "diff 변경 0" | 스냅샷 쓰기가 EACCES 로 실패해 **낡은 파일끼리** 비교했다 |
| "경로 탈출 차단됨" | curl 이 **클라이언트에서** `../` 를 정규화해 서버는 그 요청을 본 적이 없다 |

→ 규칙: **초록을 보면 그 초록이 무엇을 봤는지 한 번 더 확인한다.**
  파일이면 크기·mtime 을, 원격이면 코드가 도착했는지를, 종료코드면 파이프가 가리지 않았는지를.
