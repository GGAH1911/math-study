# 자율 InteractiveSpec 생성 루프 — 설계 블루프린트 (v2)

> 개념 노드마다 **검증된 인터랙티브 시각화 위젯(InteractiveSpec)** 을 자동 생성하는, 감독 없이 도는 루프.
> 작성: 2026-06-26 · 상태: 설계(미구현) · 선행 PoC: 사인 위젯(삼각비의_정의) 통합 완료

---

## 0. 배경 (왜 이게 있나)

- **redraw(기출 도형 벡터 재현)는 실익 재평가에서 저ROI 판정** — 원본 추출이 이미 되어 정적 사본은 가치가 낮음. 블랭킷 전수 중단.
- 사장님 판단: **코어 가치 = 개념 이해 깊이**. EBS·메가 기출앱과의 차별점은 LLM 튜터 + "이해시키는 인터랙티브 시각화".
- redraw의 생성 인프라(렌더러 + spec + LLM measure)는 **개념 위젯**으로 계승. 단 출력이 정적 도형이 아니라 **인터랙티브(고가치)**.
- 우리에겐 이미 **`Interactive.tsx`**(선언형: params 슬라이더 + mathjs scope + Geometry/Graph/3D) + **버튼→모달 패턴**(ChatPanel)이 있음 → 바퀴 재발명 불필요.
- 파일럿(Opus 30노드 분류): 시각 개념의 **93%가 위젯 가치**, **거의 100% InteractiveSpec 적합**, **슬라이더 중심**(모바일 안전). → 인프라는 **spec-driven** 확정.
- gemma4 비교(같은 30): **부적합**(루프·무분별·malformed). 판단·생성·검증은 **Opus 전용**.

관련 메모리: `project_concept_widgets`, `project_redraw_pipeline`, `reference_gemma4_macbook`, `project_katex_system`, `project_solution_cache`.

## 1. 목표 / 비목표

**목표**: 분류된 시각 노드 큐를 받아, 노드마다 **렌더·수학·교육 검증을 통과한 InteractiveSpec**을 만들어 repo에 영속. **사람 입력 없이** 큐가 빌 때까지 또는 예산 소진까지 자율 운영.

**비목표(이번 단계)**: 본문 버튼→모달 셸 전수 통합(검증된 spec 확보 후), 전 도메인 동시 처리, 런타임 위젯 생성.

## 2. 설계 원칙 — 각 원칙이 닫는 약점

v1 설계 자가평가에서 드러난 5개 구멍을 각각 근본 해결한다.

### ① 검증 엄밀성 — 정답을 어떻게 자동으로 아는가
- **이중유도(differential testing)**: 생성기가 spec과 함께 그 개념의 *정의식*과 *검증레시피*(샘플 파라미터값)를 산출. 검증기는 정의식에서 **sympy로 독립 유도**한 값과 spec의 scope 출력을 **여러 슬라이더값에서 대조**. 두 독립 계산이 어긋나면 reject. → 노드별 정답 하드코딩 불필요.
- **속성/불변식 검사**(하드코딩 0): 모든 슬라이더값에서 성립해야 하는 것 — `sin²+cos²=1`, 곡선 위 점은 방정식 만족, 접선 기울기 = f′(x), 다각형 내각합 = (n−2)·180° 등. 정답 없이도 옳음을 강제.
- **교육게이트 노이즈 제거**: 단일 LLM 판단(±3-4 노이즈, redraw 교훈) 대신 **결정적 체크리스트**(분류 스케치가 요구한 핵심 요소 포함?) + **3중 판정 다수결**(독립 verifier 3, 과반).

### ② 자율성 — 런타임 인간 의존 0
- 루프는 **워커풀 + 큐** 자기완결 스크립트. 재투입·재시도·스킵 전부 스크립트가 자동 처리.
- **도는 동안 사람/감독 LLM의 판단 0개** — 모든 결정은 결정적 게이트 또는 다수결 게이트로 박제. 설계자·최종 리뷰어는 런타임 의존성이 아님.

### ③ 견고성 — false-positive와 하네스 조용한 붕괴
- **카나리아 셀프테스트**: 매 실행 전, *정답 spec(사인)* 은 통과하고 *고의로 깨뜨린 spec* 은 reject 되는지 확인. 둘 중 하나라도 어긋나면 **검증기 고장 → 큐 처리 중단(HALT)**. 조용한 오통과 차단.
- **비대칭 수용(asymmetric accept)**: 무위젯은 안전, **오위젯은 오류 출고**. 그래서 *애매하면 무조건 skip-to-manual*(false-negative ≫ false-positive). 모든 하드게이트 + 다수결 통과여야만 accept.

### ④ 실현가능성 — 검증 안 된 전제 위 과설계
- **단계 go/no-go 내장**: 미니실험과 풀루프가 **같은 파이프라인**. `N=5` 먼저 → 자동 집계 → **합격률 ≥ 임계(예 4/5)** 넘어야 자동 스케일. 못 넘으면 **스스로 중단 + 보고**. "먼저 검증"이 별도 단계가 아니라 구조에 박힘 → 과설계 불가.

### ⑤ 관측·감독성 — 렌더 ≠ 정답
- 갤러리가 "그럴듯함"이 아니라 **증거**를 표시: 오라클 대조표(샘플값별 spec ↔ 독립유도), 불변식 ✓/✗, 3판정표.
- accepted / needs-manual / rejected **큐 + 증거 기반 승인·반려** 워크플로(대규모 리뷰 가능).

## 3. 파이프라인 (노드 1개 = 1 레인, 파이프라인 병렬)

```
0  카나리아     정답spec 통과 & 깨진spec reject 확인 → 실패면 전체 HALT
①  생성(Opus)   InteractiveSpec + 정의식 + 검증레시피(샘플 파라미터)
②  렌더게이트   headless /dev/interactive-test?spec= 렌더 → 에러/빈화면이면 reject
③  수학게이트★  이중유도 대조 + 불변식 — 어긋나면 reject (정답의 hard-stop)
④  교육게이트   결정적 체크리스트 + 3중 다수결(noise 평균)
⑤  수정루프     실패 게이트 피드백 주입 → Opus 재생성 → 재검증 · keep-best · 최대 3라운드
                3라운드 후도 실패 → skip-to-manual(로그)
⑥  영속         accept만 → web/src/data/concept-widgets/<id>.json + 레지스트리 매핑 + 증거
```

- **수학게이트가 hard-stop**: 틀린 위젯은 무위젯보다 나쁨(redraw의 ①본문정합성 자리).
- **keep-best**: 검증 통과한 spec은 회귀 금지(재생성이 더 나빠지면 이전 것 유지).

## 4. 자율·안전 장치 (감독 없이 도니까 핵심)

- 큐 드리븐 · **멱등**(이미 done 스킵, 재개 가능).
- **라운드 캡 + skip-log**(needs-manual): 발산 노드 3라운드 후 포기 → 토큰 안 태움.
- **캐싱 + 벌크**: 생성/검증 Opus는 clean-cwd + `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1` 캐싱. 분류는 벌크.
- **예산 가드**: 토큰/시간 상한 도달 시 정지(상태 저장). 재개 가능.
- **gemma 미사용**: 판단·생성·검증 전부 Opus(파일럿서 gemma 부적합 확인).
- **사일런트 캡 금지**: 스킵·미처리 전부 로그.
- **실패 안전**: 모든 실패 경로를 reject / HALT / skip 으로 닫음 — 무감독 루프의 점수는 정확도가 아니라 **실패 안전성**이 가른다.

## 6. 단계 롤아웃 (go/no-go)

```
Stage 0  카나리아 셀프테스트 (정답/오답 spec)             → 실패면 HALT
Stage 1  N=5 노드 생성+검증 → 합격률 집계                  → < 임계면 중단+보고("spec생성 비현실적")
Stage 2  ≥ 임계면 자동으로 함수/도형 후보 전수 스케일       → 큐 소진 or 예산까지
Stage 3  최종 보고 + accepted spec repo 영속 + needs-manual 리스트
```

미니실험이 곧 풀루프의 첫 단계라, "검증 먼저"가 구조적으로 보장된다.

## 8. 정직한 단서 (이게 진짜 10점의 조건)

- 이 설계의 린치핀은 **이중유도 오라클**이며, 그것 자체가 **카나리아(Stage 0)와 N=5(Stage 1)에서 먼저 증명**돼야 한다. 다만 그게 **루프의 첫 게이트**라 틀리면 스스로 멈춘다(자기교정).
- 즉 강함의 근거는 "완벽해서"가 아니라 **틀려도 안전하게 틀리고(비대칭 수용·카나리아·HALT), 전제가 안 맞으면 스스로 접는(go/no-go)** 데 있다.
- 다음 한 수: `검증 하네스 + 이중유도 검증기 + 워커풀`을 만들고 **Stage 0~1(카나리아 + N=5 go/no-go)** 부터 가동.
