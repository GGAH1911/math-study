## Phase 0 — 지금 웹에서도 문제인 것 (앱과 독립)

앱을 안 만들어도 고쳐야 하는 것들. **사장님이 지금 쓰는 제품이 바로 좋아진다.**

- [ ] **튜터 첨부 이미지가 다음 턴에 사라지는 문제** — `formatHistory` 가 텍스트만 넘긴다.
      필기 채점이 코어인데 **한 턴짜리**다. → 최근 1-2턴 이미지 유지 + 첫 턴 전사 요약 병행
- [ ] **chat_history jsonb 비대화** — 대화 1건 568KB. 이미지를 R2 로 분리하고 참조만 남긴다
      (2MB 상한은 약 30장에서 걸리므로 급한 불은 아니지만, jsonb 비대화 자체가 문제)
- [ ] **이미지 리사이즈 정책 재결정** — 현재 표시용 512px 다운스케일이 이미 들어간다.
      1,600px 로 올릴지 512px 를 유지할지 **판독 충실도 vs 저장량**으로 정하고 근거를 남긴다
- [ ] **WebP 서빙** — ★1차는 **서빙 계층 매핑까지만**(본문·코드의 경로 문자열은 건드리지 않는다).
      실제 파일 개명은 Phase 5 의 매니페스트·내용주소 작업과 한 번에 (지금 하면 4,164파일 13,819곳 일괄 치환)

**통과 조건**: 손풀이 사진 올리고 **후속 3턴이 맥락 유지** · 대화 jsonb 정상 크기 · 웹 이미지 WebP 서빙

★**업로드 실패는 가장 늦게 드러나는 실패**다. 아무것도 안 만든 상태에서 먼저 뚫는다.

- [ ] Capacitor **8** 프로젝트 생성 (targetSdk **36** · minSdk 24 · AGP 8.13.0 · Gradle 8.14.3 · Java 21)
- [ ] 서명 키 4096-bit 생성 — 비밀번호는 `keystore.properties`(gitignore) 또는 환경변수,
      **소스에 넣지 않는다**. 둘 다 없으면 **빌드가 멈추게** 한다
- [ ] `.gitignore` 패턴 `release.keystore*` · `keystore.properties*`
- [ ] AAB 빌드 → **내부 테스트 트랙 업로드** → 실기기 설치·구동
- [ ] **N2 결과가 개인 계정이면**: 비공개 테스트 트랙 개설 + **테스터 12명 모집 착수**

**통과 조건**: 기능 0 인 앱이 업로드·구동 · 계정 종류 확정 · (개인 계정이면) 테스터 모집 진행 중

## Phase 3 — SSR 제거 → SPA + JSON API ★최대 공사

**앱 프로젝트의 절반 이상.** 임계 경로의 시작점이고, 여기가 늦으면 전부 늦는다.

- [ ] **사용자 대면 25개** 페이지를 클라이언트 렌더링으로 (전체 45개 중 `/dev` 20개는 SSR 유지)
      → `/dev` 를 SSR 로 남기면 "tme 는 API 만" 과 충돌하므로 존치 방식을 여기서 정한다
- [ ] 인증 게이팅을 서버 미들웨어 → 앱 라우팅으로
- [ ] **세션 쿠키 → access/refresh 토큰** (Keychain/Keystore 보관)
- [ ] ★**동일출처 CSRF 폐기 → 베어러 토큰 + CORS 화이트리스트**
      (웹 도메인 · `capacitor://localhost` · `https://localhost`). `middleware.ts:83-88` · `auth.ts:124`
      **이 공사 없이는 앱이 아예 못 뜬다** — 모든 쓰기가 403
- [ ] ★**`/problem-images/` 게이팅 대체** — 토큰 전환과 **같은 릴리스에**. 서명 URL 또는 단수명 쿠키.
      안 하면 무인증 스크래핑이 열리면서 동시에 이미지 표시가 깨진다
- [ ] ★**마크다운 렌더 파이프라인 이전** — remark 4종 + rehype-katex 를 클라이언트 포팅하거나
      빌드 시 선렌더. **링크 재작성은 원리적으로 브라우저에서 못 돈다**
- [ ] Worker 가 검증할 **단수명 JWT 발급 엔드포인트** (Phase 5 서명 URL 의 전제)

**위험**: 사장님이 매일 쓰는 웹을 고치는 작업 → **페이지 단위 점진 이전**, 45개를 한 번에 뒤집지 않는다.

**통과 조건**: 웹이 SPA 로 완전 동작 · 기존 기능 회귀 0 · **미로그인 상태에서 `/problem-images` 직접 요청 차단 유지**

## Phase 4 — 데이터 재설계 (Phase 3 과 병렬 가능)

- [ ] ★**선행**: `problem-state.ts:67-80` 의 `reset`·`mark-mastered`·`skip` 과
      `mastery-promote.ts:43` 의 evidence 를 **이벤트로 전환**.
      이걸 안 하고 재계산하면 **지운 상태가 되살아나고 evidence 가 사라진다**

- [ ] `InkCanvas.tsx:207` 의 로컬 우선 pull 스킵 제거 → **seq 비교 후 병합**
- [ ] 서버 부여 **seq** + 커서 기반 델타 동기화 API

**통과 조건**: 두 기기 오프라인 작업 합류 시 **소실 0** · 재계산 후 evidence·mark-mastered·skip **보존**

## Phase 5 — 인프라 (★Phase 3 뒤. 병렬 아님)

Pages 가 배포할 SPA 자체가 Phase 3 산출물이고, 호스트 분리가 동일출처 검사를 깨뜨린다.

- [ ] **R2 버킷** (콘텐츠 · 필기 · 튜터 이미지) — 포렌식과 이름 분리
- [ ] **네임드 터널 + 도메인** (임시 `--url` 아님 — 앱은 고정 주소 필요) → `MS_SECURE_COOKIES=true`
- [ ] **Workers** — 단수명 JWT 서명 검증 → R2 서명 URL 발급 (DB 조회 없음 → 서버 부하 0)
- [ ] **Pages** SPA 배포
- [ ] **콘텐츠 매니페스트** — 스키마 버전 + 내용주소(해시 파일명) + 회차 단위
- [ ] **WebP 파일 개명** 확정 (Phase 0 에서 미룬 것) — 4,164파일 13,819곳 + 인제스트 파이프라인
- [ ] **최근 1-2회차 프리번들** (약 2.4MB) — 4.2 심사 시연 경로
- [ ] **DB 백업 상시화** (N1 을 운영 절차로) — ★**DB 와 R2 를 같은 시점으로 묶는다**
- [ ] **장애 알림** — 헬스체크 3연속 실패 시 폰으로

**통과 조건**: **미인증** 다운로드 차단 · 오프라인 문제 열람 · 빈 DB 복원 후 로그인·필기 로드 ·
헬스체크 실패 알림 **실제 도착** · 웹 SPA 가 tme API 를 크로스오리진 호출해 로그인·필기저장·탈퇴 성공

## 임계 경로

```
N1·N2 (오늘)
   │
Phase 0 ─┐
Phase 2 ─┤ (병렬)
Phase 4 ─┘
   │
Phase 3 (SSR 제거) ──▶ Phase 5 (인프라) ──▶ [필기 판정] ──▶ Phase 6 ──▶ 7 ──▶ 8
```

**개인 계정이면 Phase 8 의 14일 게이트가 별도 리드타임**이므로, Phase 2 에서 테스터 모집을 시작해
임계 경로 밖으로 뺀다.

## 일정을 흔들 수 있는 것

1. **필기 지연 미달** → D안 추가(필기 네이티브 + 브리지 설계)
2. **SSR 제거가 예상보다 큼** → 25개 페이지의 상태·인증 의존이 얽힌 정도에 달렸다
3. **심사 반려** → 4.2 가 주 위험. **오프라인·펜·결제가 다 들어간 뒤** 제출한다
4. **12명 × 14일** → 개인 계정일 때만. 조직 계정이면 소멸
